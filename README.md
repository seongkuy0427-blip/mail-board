# mail-board — 업무 대시보드

회사 웹메일(`mail.chunil.co.kr`)로 들어오는 업무 요청을 PC·모바일 브라우저에서
한눈에 보는 **암호화된 정적 대시보드**입니다.

- 배포 주소: https://seongkuy0427-blip.github.io/mail-board/
- 구조: 정적 HTML + 암호문(`data.enc.json`)만 공개. 실제 내용은 **PIN을 알아야만 복호화**됩니다.
- 저장소가 public이어도 메일 내용·품번·고객사 정보는 평문으로 노출되지 않습니다.

## 화면 구성

| 영역 | 내용 |
|---|---|
| 상단 KPI | 🔴 즉시 확인 / 오늘·임박 마감(2시간 이내 또는 지남) / 회신 필요 / 완료 |
| 새 메일 알림 | 자동 재조회(5분)·새로고침에서 **새 🔴 즉시 확인 건**이 들어오면 ① 화면 상단 빨간 알림 카드(닫기 가능 · ‘메일 보기’로 해당 메일 열기) ② 탭 제목 `🔴 [새 메일] …` ↔ `📧 회사 메일 보드` 깜빡임(클릭하면 원래 제목으로 복구) ③ 화면 토스트, 그리고 🔔 를 켜 둔 경우 브라우저 팝업으로 알려줍니다. **회사 PC에서 Windows 알림이 차단되어 팝업이 안 뜰 때도 ①②는 그대로 뜹니다** |
| 알림 테스트 | 상단 `🔔 알림 테스트` 를 누르면 팝업 권한과 무관하게 상단 알림 카드 + 탭 제목 깜빡임을 바로 보여줍니다 (팝업이 허용된 브라우저에서는 팝업까지) |
| 📅 즉시 확인 마감 캘린더 | **기본은 접힌 1줄 헤더**(오늘·이번 주 마감 건수). 누르면 월간 캘린더가 펼쳐지고 즉시 확인 `dueDate`를 건수·긴급 표시로 보여줍니다. 날짜를 누르면 그날 즉시 확인만 필터(‘전체 보기’ 토글) |
| 탭 | `🔴 즉시 확인` / `🟡 흐름 참고` / `⚪ 단순 공유` — 단순 공유는 기본 숨김이고 탭을 누르거나 검색할 때만 보입니다 |
| 사람별 칩 | 발신자별 필터 칩 + ‘사람별로 묶어보기’ 그룹 보기 (최우선 등급은 1-1, 주요 등급은 1-2로 앞에) |
| 업무 행 | **컴팩트 1~2줄 행**: 분류 배지(🔴/🟡/⚪ · 등급 1-1/1-2/1-3), 제목, 발신자·수신시각, 첨부 1줄 요약, 🖼 사진 장수, 마감·남은시간 배지, 회신 여부·진행상태 배지 |
| 상세 드로어 | 행을 누르면 **PC는 우측 패널 / 모바일은 하단 시트**로 열립니다. 섹션 순서는 **① 메음 원문**(보낸사람·수신시각·마감 + 본문 표 + 본문 텍스트 + **본문 사진(누르면 크게 보기)** + 첨부파일) → **② 핵심 분석**(한 줄 요약) → **③ 할 일** 체크리스트 → **④ 히스토리**(이전 메일 타임라인) → **⑤ 답장 메일 문구 제안**(복사·mailto). 아래 고정 푸터에 회신 여부 전환·진행상태·원본 링크, 본문 끝에 내 메모 |
| 회신 관리 | `회신 필요` / `회신 완료` / `회신 불필요` — **업무 행의 회신 배지를 누르면 드로어를 열지 않고 바로 전환**(회신 필요 → 회신 완료 → 회신 불필요 → 회신 필요 순환, localStorage 저장 · 상단 KPI 즉시 갱신). 상단 ‘회신 필요만 보기’ 필터. 보낸편지함에 회신 기록이 있으면 회신 시각과 함께 `회신 완료`로 표시 |
| 검색·정렬 | 제목·발신자·품번·내용 검색(단순 공유·이전 기록 포함), 정렬(긴급도·마감순 / 마감 임박순 / 최신 수신순) |

### 분류 기준 (`priority` · `vipRank`)

| 구분 | 기준 |
|---|---|
| 🔴 즉시 확인 (`priority: 1`) | 1-1 최우선 발신 · 1-2 주요 발신 + 내가 수신인(To) · **본문에서 ‘김성규’를 직접 지목**한 메일 (인용 헤더의 `Cc:` 줄만 있는 경우는 제외) |
| 1-1 (`vipRank: 1`) | 최우선 발신자 — 수신/참조와 무관하게 1순위 맨 위 고정. 화면 표기는 `1-1 최우선` |
| 1-2 (`vipRank: 2`) | 주요 발신자 + 본인이 직접 수신인(To). 화면 표기는 `1-2 주요` |
| 1-3 (`vipRank: 3`) | 본문에서 ‘김성규’를 직접 지목한 메일. 화면 표기는 `1-3 지목` |
| 🟡 흐름 참고 (`priority: 2`) | 고객사(@gm.com)·MC↔GM 왕복, 사내 주요 이슈·결품·PTR·조직 공지 — 내가 이름으로 지목된 건 아니라서 모니터링하는 건 |
| ⚪ 단순 공유 (`priority: 3`) | 출하리스트·납입요청·재고실사·미상차현황 등 현장 일상 — 기본 숨김. **제목에 `출하리스트`·`납입요청`·`미상차현황` 이 있으면 수신인(To)이어도 단순 공유** |

**표시 범위:** `make_data.py` 의 `SINCE`(현재 `2026-11-19`) 이후 수신분만 대시보드에 들어갑니다. 이전 날짜 메일은 원본에서 걱정 없이 걸러집니다.

같은 건으로 오간 메일(Re:/Fwd:, 같은 출하리스트 차수 등)은 카드 1건으로 묶고, 최신 메일을 본문으로 두며 상세의 ‘이전 메일 타임라인’에서 나머지를 봅니다.

> 배지·필터 칩·정렬 안내에는 발신자 실명을 쓰지 않고 `1-1 최우선` / `1-2 주요` 같은 중립 등급명만 표시합니다(사무실 화면 노출 대비). 개별 행의 발신자 칸에는 일반 메일처럼 보낸 사람 이름이 그대로 나옵니다.

진행상태·회신여부·메모·체크리스트는 서버로 보내지 않고 브라우저(localStorage)에만 저장됩니다.

## 저장소에 올라가는 파일 / 안 올라가는 파일

| 파일 | 공개 | 설명 |
|---|---|---|
| `index.html` | ✅ | 대시보드 UI (데이터 없음) |
| `data.enc.json` | ✅ | 암호문 (PBKDF2-SHA256 100,000회 + AES-256-GCM) |
| `build_data.py` | ✅ | `data.json` → `data.enc.json` 암호화 스크립트 |
| `publish.sh` | ✅ | main·gh-pages 동시 배포 스크립트 |
| `data.json` | ❌ | **평문 데이터.** `.gitignore` 등록 |
| `images_data.py` | ❌ | **본문 사진 base64.** `.gitignore` 등록 (웹메일 `.eml` → WebP 추출) |
| `make_data.py` | ❌ | **메일 내용이 들어 있는 생성 스크립트.** `.gitignore` 등록 |

> `data.json` 과 `make_data.py` 는 로컬에만 두세요. 한 번이라도 push 하면 암호화가 무의미해집니다.

## 갱신 절차

```bash
cd ~/mail-board

# 0) (본문 사진이 있는 메일) 웹메일에서 .eml 로 내려받아 사진 추출 — work/build_images.py → images_data.py
# 1) make_data.py 의 ITEMS 에 새 메일 항목을 추가·수정 (첨부는 파일명·크기만)
python3 make_data.py                  # -> data.json (images 필드 포함, 사진은 WebP data URI)

# 2) 암호화 (PIN은 인자 또는 환경변수로만)
MAILBOARD_PIN=**** python3 build_data.py   # -> data.enc.json

# 3) 배포
./publish.sh "update: 납입요청 반영"
```

### 브랜치 구성 (중요)

- GitHub Pages 소스는 **`gh-pages` 브랜치 / (root)** 입니다. 사이트는 이 브랜치에서 나갑니다.
- `main` 에는 같은 파일 + 스크립트가 들어 있습니다.
- `git push origin main` 만 하면 **사이트는 바뀌지 않습니다.** 반드시 `./publish.sh` 를 쓰세요.
- (저장소 Settings → Pages 에서 소스를 `main` 으로 바꾸면 이후에는 `git push` 만으로 반영됩니다.)

## 보안 메모

- PIN은 짧은 숫자입니다. 이론상 대입이 가능하므로, 민감도가 높아지면 6자리 이상으로 바꾸는 것을 권장합니다.
- 암호문에 반복 횟수·salt가 함께 저장되므로 `--iterations` 를 올려도 페이지가 자동으로 맞춰 복호화합니다.
- "이 기기에서 로그인 유지"를 체크하면 PIN이 그 브라우저의 localStorage에 저장됩니다. 공용 PC에서는 체크하지 마세요.
- 페이지에는 `noindex` 가 걸려 있지만, 주소를 아는 사람은 누구나 접속할 수 있습니다(내용은 PIN 없이는 볼 수 없음).
