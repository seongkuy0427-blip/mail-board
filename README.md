# mail-board — 업무 대시보드

회사 웹메일(`mail.chunil.co.kr`)로 들어오는 업무 요청을 PC·모바일 브라우저에서
한눈에 보는 **암호화된 정적 대시보드**입니다.

- 배포 주소: https://seongkuy0427-blip.github.io/mail-board/
- 구조: 정적 HTML + 암호문(`data.enc.json`)만 공개. 실제 내용은 **PIN을 알아야만 복호화**됩니다.
- 저장소가 public이어도 메일 내용·품번·고객사 정보는 평문으로 노출되지 않습니다.

## 화면 구성

| 영역 | 내용 |
|---|---|
| 상단 KPI | 🔴 즉시 확인 / 오늘·임박 마감(2시간 이내 또는 지남) / 회신 필요 / 완료 |
| 새 메일 알림 | 자동 재조회(5분)·새로고침에서 **새 🔴 즉시 확인 건**이 들어오면 ① 화면 상단 빨간 알림 카드(닫기 가능 · ‘메일 보기’로 해당 메일 열기) ② 탭 제목 `🔴 [새 메일] …` ↔ `📧 회사 메일 보드` 깜빡임(클릭하면 원래 제목으로 복구) ③ 화면 토스트, 그리고 🔔 를 켜 둔 경우 브라우저 팝업으로 알려줍니다. **회사 PC에서 Windows 알림이 차단되어 팝업이 안 뜰 때도 ①②는 그대로 뜹니다** |
| 알림 테스트 | 상단 `🔔 알림 테스트` 를 누르면 팝업 권한과 무관하게 상단 알림 카드 + 탭 제목 깜빡임을 바로 보여줍니다 (팝업이 허용된 브라우저에서는 팝업까지) |
| 🌤️ 날씨 칩 | 헤더 오른쪽 아래 줄에 `🌤️ 인천 부평 -2°C` 칩. 비·눈 예보가 있는 날만 `· ⚠️ 11/23(월) 비 87%` 가 붉게 붙습니다. 칩을 누르면 **시간별(앞으로 24시간)·7일 주간** 드롭다운이 열리고, 바깥을 누르거나 Esc 로 닫힙니다(본문 자리를 차지하지 않음). 강수확률 20% 미만·풍속 숫자는 표시하지 않고, 바람은 14m/s 이상일 때만 `💨 강풍` 으로 표시합니다. 자료는 **Open-Meteo 무료 API(키 없음)** 이며 데이터 갱신(5분)과 함께 다시 받아 옵니다. |
| 📅 내 캘린더 (수동) | **자동 채우기를 쓰지 않습니다.** 행·드로어의 `📅 캘린더` 버튼을 눌러 직접 등록한 메일만 보입니다(`mb_cal_items_v1`, 기본 날짜 = 마감일 또는 오늘, 드로어의 날짜 `input[type=date]`로 변경). 헤더는 `▸ 📅 내 캘린더 · 등록 N건 · 눌러서 펼치기`. 펼치면 PC는 **2단**(왼쪽: 월간 달력 + `＋ 직접 일정 추가`, 오른쪽: 선택한 날짜 상세) · 모바일은 위아래로 쌓입니다. 달력은 `일~토`이며 **토요일 파랑(#2563eb) / 일요일·공휴일 빨강(#dc2626)**, 날짜 칸에 공휴일 이름을 표기합니다(2026~2027 법정·대체공휴일 맵). |
| 📌 직접 일정 | 달력 위 `＋ 직접 일정 추가`(날짜·제목·메모)로 **메일과 무관한 개인·구두 일정**을 넣습니다(`mb_cal_custom_v1`). 날짜 칸에 `📌`, 오른쪽 상세 패널에는 `📌 개인/구두` 배지와 메모, `✕` 삭제가 나오고 헤더의 `등록 N건`에 합산됩니다. |
| ✅ 확인 (한 번에 치우기) | 행·드로어의 `✅ 확인` 을 누르면 그 메일이 **기본 목록에서 바로 숨겨집니다**(완료 상태 · 상단 KPI `완료`에 반영). 검색어를 입력하거나 툴바의 `완료 포함` 을 켜면 다시 보이고, `↩ 취소` 로 되돌릴 수 있습니다. |
| 탭 | `🔴 즉시 확인` / `🟡 흐름 참고` / `⚪ 단순 공유` / `⏳ 미회신 추적` / `📌 고정` — 단순 공유는 기본 숨김이고 탭을 누르거나 검색할 때만 보입니다 |
| 📌 고정 (Pin) | 행 오른쪽 `📌` 또는 상세 드로어 상단 `📌 고정` 을 누르면 그 메일을 고정합니다(`mb_pinned_v1`). **분류(🔴·🟡·⚪)·`✅ 확인`·이전 기록(archived)과 상관없이 `📌 고정` 탭에 고정을 풀기 전까지 계속 남아 열람**할 수 있습니다. 탭 배지에 고정 건수가 항상 표시되고(0건이어도 탭 유지), 일반 탭에서도 고정한 건은 목록 맨 위로 올라오며 제목 앞 `📌`·행 오른쪽 `📌 고정됨`(주황)으로 보입니다. 다시 누르면 고정이 풀립니다. |
| ⏳ 미회신 추적 | **내가 상대(협력사·타 부서·담당자·고객사)에게 답변·자료·승인·조치 회신을 요청한 메일** 중 아직 회신이 확인되지 않은 것만 모읍니다(`followups`). 업무 완료 보고·자료 제출、답장(RE:)·공지·단순 전달은 자동 제외 — 2026-11-19 기준 **0건**이며, 그때 탭은 “현재 회신을 기다리는 요청 메일이 없습니다. (완료 보고·자료 제출 메일은 자동 제외)”로 표시됩니다. 상단 KPI `⏳ 미회신 대기`·탭 배지에 건수가 나오고, 행은 `⏳ 미회신 N일째` + 제목 + 받는사람 + 보낸 날짜의 1~2줄입니다. 행을 누르면 드로어에서 **보낸 원문 → 요청 요약(+미회신 확인 근거) → 독촉/확인 메일 문구(`📋 복사` / `mailto:`)** 를 보고, 하단 `회신 받음(추적 완료)` / `계속 대기` 로 상태를 바꿉니다(localStorage 저장 · 완료 시 대기 건수에서 즉시 차감). |
| 사람별 칩 | 발신자별 필터 칩 + ‘사람별로 묶어보기’ 그룹 보기 (최우선 등급은 1-1, 주요 등급은 1-2로 앞에) |
| ⚙️ 분류 규칙 | 헤더 오른쪽 `⚙️` 를 누르면 **발신자 주소록**(지금까지 오간 메일의 발신자를 모아 검색·직접 추가)과 **제목 키워드**에 `🔴 즉시` / `🟡 숙지` / `⚪ 열람` 등급을 지정할 수 있습니다. `저장 및 즉시 반영` 을 누르면 새로고침 없이 KPI·탭 건수·목록이 다시 분류되고, `커스텀 규칙 초기화` 로 기본 분류로 돌아갑니다(이 브라우저 `mb_rules_v1` 에만 저장). |
| 업무 행 | **컴팩트 1~2줄 행**: 분류 배지(🔴/🟡/⚪ · 등급 1-1/1-2/1-3), 제목, 발신자·수신시각, 첨부 1줄 요약, 🖼 사진 장수, 마감·남은시간 배지, 회신 여부·진행상태 배지 |
| 상세 드로어 | 행을 누르면 **PC는 우측 패널 / 모바일은 하단 시트**로 열립니다. 섹션 순서는 **① 메음 원문**(보낸사람·수신시각·마감 + 본문 표 + 본문 텍스트 + **본문 사진(누르면 크게 보기)** + 첨부파일) → **② 핵심 분석**(한 줄 요약) → **③ 할 일** 체크리스트 → **④ 히스토리**(이전 메일 타임라인) → **⑤ 답장 메일 문구 제안**(복사·mailto). 아래 고정 푸터에 회신 여부 전환·진행상태·원본 링크, 본문 끝에 내 메모 |
| 회신 관리 | `회신 필요` / `회신 완료` / `회신 불필요` — **업무 행의 회신 배지를 누르면 드로어를 열지 않고 바로 전환**(회신 필요 → 회신 완료 → 회신 불필요 → 회신 필요 순환, localStorage 저장 · 상단 KPI 즉시 갱신). 상단 ‘회신 필요만 보기’ 필터. 보낸편지함에 회신 기록이 있으면 회신 시각과 함께 `회신 완료`로 표시 |
| 검색·정렬 | 제목·발신자·품번·내용 검색(단순 공유·이전 기록 포함), 정렬(긴급도·마감순 / 마감 임박순 / 최신 수신순). 검색창 옆 `🔎 웹메일 1년 검색` 은 입력한 말을 회사 웹메일의 지난 1년 받은편지함(`s_date=365`)에서 바로 검색해 줍니다. |

### 분류 기준 (`priority` · `vipRank`)

| 구분 | 기준 |
|---|---|
| 🔴 즉시 확인 (`priority: 1`) | 1-1 최우선 발신 · 1-2 주요 발신 + 내가 수신인(To) · **본문에서 ‘김성규’를 직접 지목**한 메일 (인용 헤더의 `Cc:` 줄만 있는 경우는 제외) |
| 1-1 (`vipRank: 1`) | 최우선 발신자 — 수신/참조와 무관하게 1순위 맨 위 고정. 화면 표기는 `1-1 최우선` |
| 1-2 (`vipRank: 2`) | 주요 발신자 + 본인이 직접 수신인(To). 화면 표기는 `1-2 주요` |
| 1-3 (`vipRank: 3`) | 본문에서 ‘김성규’를 직접 지목한 메일. 화면 표기는 `1-3 지목` |
| 🟡 흐름 참고 (`priority: 2`) | 고객사(@gm.com)·MC↔GM 왕복, 사내 주요 이슈·결품·PTR·조직 공지 — 내가 이름으로 지목된 건 아니라서 모니터링하는 건 |
| ⚪ 단순 공유 (`priority: 3`) | 출하리스트·납입요청·재고실사·미상차현황 등 현장 일상 — 기본 숨김. **제목에 `출하리스트`·`납입요청`·`미상차현황` 이 있으면 수신인(To)이어도 단순 공유** |

**표시 범위:** `make_data.py` 의 `SINCE`(현재 `2026-11-19`) 이후 수신분만 대시보드에 들어갑니다. 이전 날짜 메일은 원본에서 걱정 없이 걸러집니다.

같은 건으로 오간 메일(Re:/Fwd:, 같은 출하리스트 차수 등)은 카드 1건으로 묶고, 최신 메일을 본문으로 두며 상세의 ‘이전 메일 타임라인’에서 나머지를 봅니다.

> 배지·필터 칩·정렬 안내에는 발신자 실명을 쓰지 않고 `1-1 최우선` / `1-2 주요` 같은 중립 등급명만 표시합니다(사무실 화면 노출 대비). 개별 행의 발신자 칸에는 일반 메일처럼 보낸 사람 이름이 그대로 나옵니다.

진행상태·회신여부·메모·체크리스트는 서버로 보내지 않고 브라우저(localStorage)에만 저장됩니다.

### ⚙️ 내 분류 규칙 (`mb_rules_v1`)

`data.json` 이 내려준 기본 분류(`priority` · `vipRank`)는 그대로 두고, 헤더의 **⚙️** 에서 지정한 규칙만 그 위에 덧씌웁니다.

- **발신자별 등급** — 지금까지 오간 메일의 발신자를 주소록으로 모아 보여줍니다(이름·이메일 검색, 주소록에 없는 사람은 직접 추가). 사람마다 `기본` / `🔴 즉시` / `🟡 숙지` / `⚪ 열람` 중 하나를 고르고, 필요하면 `To만` 을 켜서 **직접 수신인(To)일 때만** 적용되게 합니다. `기본` 으로 되돌리면 그 사람 규칙은 지워집니다.
- **제목 키워드** — `긴급` · `용기승인` · `정례회의` · `출하리스트` 처럼 제목에 들어간 단어로 등급을 지정하고 지웁니다.
- **적용 순서** — 발신자 규칙 → 제목 키워드 규칙 → 기본 분류. 규칙이 적용된 메일은 행 발신자 줄과 상세 배지에 `⚙️ 내 규칙` 이 붙습니다.
- `저장 및 즉시 반영` → KPI · 탭 건수(`🔴`·`🟡`·`⚪`)·목록이 새로고침 없이 다시 계산됩니다. `커스텀 규칙 초기화` → 규칙을 모두 지우고 기본 분류로 복귀합니다.
- 규칙은 서버로 보내지 않고 **이 브라우저(localStorage)에만** 저장됩니다. 다른 기기·다른 브라우저에는 적용되지 않습니다.

### ⏳ 미회신 추적 기준

- 대상: 보낸편지함(Sent) **2026-10-30 ~ 11-19**. 그 기간 보낸 메일 중 **상대에게 답변·자료·승인·조치 회신을 꼭 받아야 하는 요청**만 담습니다.
- **자동 제외**: 상사·요청자에게 보낸 업무 완료 보고·자료 제출(끝에 “확인 부탁드립니다”가 붙은 경우 포함), 받은 메일에 대한 답장(RE:), 공지·단순 전달(FW), 개인 메일.
- 미회신 판정: 받은편지함을 6개월 범위에서 같은 제목·상대·키워드로 검색해 회신이 없음을 확인하고, 그 근거를 각 항목의 `evidence`로 남깁니다.
- **2026-11-19 기준 0건** — 최근 3주 보낸편지함은 보고·제출·답장·공지가 대부분이고, 회신을 기다리는 요청 메일은 없습니다. 새 요청이 생기면 30분 자동 업데이트가 `followups`에 추가합니다.

## 갱신 절차

```bash
cd ~/mail-board

# 0) (본문 사진이 있는 메일) 웹메일에서 .eml 로 내려받아 사진 추출 — work/build_images.py → images_data.py
```

### 브랜치 구성 (중요)

- GitHub Pages 소스는 **`gh-pages` 브랜치 / (root)** 입니다. 사이트는 이 브랜치에서 나갑니다.
- `main` 에는 같은 파일 + 스크립트가 들어 있습니다.
- `git push origin main` 만 하면 **사이트는 바뀌지 않습니다.** 반드시 `./publish.sh` 를 쓰세요.
- (저장소 Settings → Pages 에서 소스를 `main` 으로 바꾸면 이후에는 `git push` 만으로 반영됩니다.)

## 보안 메모

- PIN은 짧은 숫자입니다. 이론상 대입이 가능하므로, 민감도가 높아지면 6자리 이상으로 바꾸는 것을 권장합니다.
- 암호문에 반복 횟수·salt가 함께 저장되므로 `--iterations` 를 올려도 페이지가 자동으로 맞춰 복호화합니다.
- "이 기기에서 로그인 유지"를 체크하면 PIN이 그 브라우저의 localStorage에 저장됩니다. 공용 PC에서는 체크하지 마세요.
- 페이지에는 `noindex` 가 걸려 있지만, 주소를 아는 사람은 누구나 접속할 수 있습니다(내용은 PIN 없이는 볼 수 없음).
